# Progress update, 25 November 2026
**Detecting wing damage on a flapping-wing drone from its onboard IMU and microphone**

## 1. Where the project stands
The first pipeline (June–July) reported ROC-AUC 0.93 for healthy vs damaged wings. Before
building on it, I audited it and started a clean rebuild that checks the data first. The checks
found three problems that change how any result must be evaluated (§2). The rebuild now has
verified data, a decisions log with a rationale for every choice (`docs/DECISIONS.md`), and a
model plan (§5). No new model results yet: they are the next step (§6).

Data: 23 usable flights (11 healthy, 12 damaged) from two recording campaigns.

## 2. Findings from checking the data
1. **The campaign predicts the label.** Campaign 1 is 1 healthy / 8 damaged flights, campaign 2
   is 10 / 4. A rule that only knows the campaign already reaches ROC-AUC **0.71** per window and
   **0.79** per flight (quick check; to be re-computed by the evaluation script).
   → Every result will be reported next to this baseline, and within campaign 2 alone.
2. **The firmware silently drops data.** During WiFi stalls longer than ~1.25 s, the board
   discards samples *before* numbering the packets, so packet IDs look continuous while data is
   missing: 0–7.3 s per recording. Each gap is located to ±48 ms, and the sizes match the firmware's
   buffer sizes. 21 % of 3-s windows contain a gap, and the share differs between classes
   (15–30 %), so a model could learn the gaps instead of the wings.
   → Windows containing a gap are excluded (decision D6).
3. **Audio and IMU are not aligned.** The offset reaches ±1.4 s and drifts by up to 0.5 s within a
   recording. It is measured per recording, and agrees with the independent data-loss estimate
   (r = 0.89 over 14 recordings).
   → Audio is re-aligned to the IMU before any fusion (D7).

Details and validation: `docs/SYNC_CHECKS.md`. Example: `docs/figures/sync_hole2_full.png`.

## 3. First look at the signals (no labels shown)
`results/eda/psd.png` (average spectrum of every flight) and `results/eda/spectrograms.png`
(spectrum over time, every flight).
- The wingbeat is a clear line near 13–14 Hz, with a harmonic near 27 Hz, in every flight.
- Its frequency moves within a flight as the drone manoeuvres, so features must tolerate that.
- Labels are deliberately hidden: features are chosen from the physics of the flapping
  mechanism and these plots, not by looking at what separates the classes (avoids selection bias).

## 5. Model plan: one classifier, increasingly flexible features
Every model ends in the same logistic regression, p(damaged) = σ(wᵀφ(x) + b); only the
features φ change:

| Rung | Features φ | Role |
|---|---|---|
| R0 | the campaign only | the shortcut to beat |
| R1 | physics features (wingbeat frequency, harmonics, …) | interpretable baseline |
| R2 | MiniRocket random convolution features | strong generic time-series features |
| R3 | the old CNN, re-run under the new evaluation | does deep learning add anything? |
| R4 | frozen pre-trained audio embeddings (AST or PANNs) | transfer from large audio data |

IMU first, then audio, then fusion. Why this order: there are only 23 independent flights, and a
model with many free parameters can fit any labelling of 23 points (Cover, 1965). Each step up in
flexibility has to earn its place.

**Planned evaluation:** leave one recording out; PR-AUC, per-class F1, false-positive rate and confusion
matrices, per window and per flight; always with the R0 row and campaign 2 alone. The protocol
is written down before any model runs.

## 7. Questions for discussion
1. **Framing:** keep the supervised classifier, add a semi-supervised (train on healthy only)
   detector, or both?
2. **Claim:** with two wing sets, the defensible claim is generalisation to unseen *flights* of
   these wings, not to unseen wings. Is that acceptable for the thesis?
3. **New recordings:** a third campaign with several wing sets, healthy and damaged flights
   interleaved and wing IDs logged would remove the campaign confound. Is there time for it?
